## Push — الجواب الصريح

**التطبيق مستقل، لكن Push الحقيقي أثناء الإغلاق يحتاج Apple Developer.**

استحقاق `aps-environment` تصدره Apple **للحسابات المدفوعة فقط**. هذه ليست
عقبة تقنية يمكن الالتفاف عليها — [Apple تنصّ عليها صراحة][apple-aps]، ولا
يوجد أي طريق رسمي حولها.

والأسوأ: ترك الاستحقاق في الإعدادات **لا يتدهور بلطف** — Xcode يرفض التوقيع
كلياً برسالة `Provisioning profile doesn't support the Push Notifications
capability`، فلا تستطيع بناء التطبيق أصلاً. لذلك يُزال في البناء المجاني.

## ما الذي يعمل فعلاً

| الحالة | النتيجة |
|---|---|
| التطبيق مفتوح | ✅ إشعار خلال 45 ثانية، **بصوت الصندوق** |
| التطبيق في الخلفية | ⚠️ أحياناً — iOS يقرّر متى يمنح تحديثاً |
| **التطبيق مُغلق تماماً** (مسحته من المبدّل) | ❌ **لا شيء** |
| النقر على الإشعار | ✅ يفتح الطلب الصحيح |

الصف الثالث هو الخسارة الحقيقية. عند إغلاق التطبيق، **iOS لا ينفّذ أي كود**
— لا مؤقّتات ولا خلفية ولا شيء. الشيء الوحيد الذي يوقظ تطبيقاً مغلقاً هو
Push بعيد، وهو بالضبط ما لا يمنحه الحساب المجاني.

لن أدّعي غير ذلك.

## ما بُني لك

- **مراقبة الطلبات**: استطلاع كل 45 ثانية أثناء فتح التطبيق فقط ← إشعار
  محلي **بصوت الصندوق الحقيقي** (لأن الحزمة حزمتنا هذه المرة)
- **مهمة خلفية**: تعمل حين يسمح iOS — أفضل المتاح، وليست ضماناً
- **منع تكرار موثوق**: علامة زمنية محفوظة في SecureStore، فإعادة فتح التطبيق
  لا تُعيد إعلان طلبات الصباح. مُختبَرة عبر الاستطلاع المتكرر والدفعات
  وإعادة التشغيل
- **تفعيل ذاتي**: يبدأ المراقب فقط حين يفشل تسجيل رمز Push — أي على الحساب
  المجاني. لو اشتركت يوماً، يتوقف وحده بلا تعديل كود، فلا إشعار مزدوج

## البناء والتثبيت

### تحتاج جهاز Mac

هذه العقبة الحقيقية، لا Push. البناء لـ iOS يتطلب Xcode، وXcode لا يعمل إلا
على macOS. تحقّقت عملياً: `expo prebuild --platform ios` يرفض على Windows
ويطلب macOS/Linux صراحة.

**EAS السحابي لا ينفع هنا** — [يتطلب شهادة توزيع وملف ad-hoc][expo-signing]،
وكلاهما يحتاج حساباً مدفوعاً.

### الخطوات على Mac

```bash
git clone https://github.com/alicherifoussama1-dot/dakkani.git
cd dakkani/apps/mobile && npm install
```

```bash
COMMERCO_FREE_SIGNING=1 npx expo prebuild --platform ios --clean
```

```bash
cd ios && pod install && open commercomerchant.xcworkspace
```

في Xcode:

1. اختر الهدف ← **Signing & Capabilities**
2. **Team** ← أضف Apple ID المجاني ← اختر `(Personal Team)`
3. غيّر **Bundle Identifier** إلى شيء فريد لك، مثل
   `store.commerco.merchant.firas` — المعرّفات المستخدمة عالمياً قد تتعارض
4. وصّل iPhone بالكابل ← اختره كوجهة ← **⌘R**

أول تشغيل: **الإعدادات ← عام ← VPN وإدارة الأجهزة ← ثِق بالمطوّر**.

### كل 7 أيام

يتوقف التطبيق عن الفتح. أعد توصيله بالـMac واضغط **⌘R**. لا تفقد بياناتك.

هذا قيد Apple على الحسابات المجانية، وحدّه الأقصى **3 تطبيقات** على الجهاز.

## الاختبار

1. افتح التطبيق وسجّل الدخول ← اقبل إذن الإشعارات
2. **أبقِ التطبيق مفتوحاً** واطلب طلباً من متجرك
3. خلال 45 ثانية: إشعار + صوت الصندوق
4. اضغطه ← يفتح الطلب

للتحقق من الإعداد قبل البناء:

```bash
cd apps/mobile && npm run test:ios-config
```

## إن غيّرت رأيك يوماً

كل إعدادات النسخة المدفوعة محفوظة سليمة. بلا `COMMERCO_FREE_SIGNING`:

```bash
cd apps/mobile && npx eas-cli build --platform ios --profile preview
```

يعطيك: Push حقيقي أثناء الإغلاق · بلا دورة 7 أيام · بلا Mac (EAS يبني
سحابياً) · صوت الصندوق عبر Push. تحتاج `APNS_KEY_P8` و`APNS_KEY_ID`
و`APNS_TEAM_ID` و`APNS_BUNDLE_ID` في Vercel — والخادم جاهز لها منذ الآن.
