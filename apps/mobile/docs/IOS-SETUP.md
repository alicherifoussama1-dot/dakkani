# iOS — ما هو جاهز، وما يحتاج إليك

آخر تحديث: 14 أوت 2026 · commit `c3cdd98`

نفس مشروع Expo يبني الآن Android و iOS. لا يوجد fork، ولا تطبيق ثانٍ،
ولا تصميم جديد. إعدادات Android لم تتغيّر بأي حرف.

---

## 1 · ما أُنجز

الشيفرة والإعدادات جاهزة بالكامل. لا يوجد كود متبقٍّ لتكتبه.

| | الحالة |
|---|---|
| `ios.bundleIdentifier` = `store.commerco.merchant` | كان موجوداً ✅ |
| `UIBackgroundModes: remote-notification` | كان موجوداً ✅ |
| نصوص الأذونات بالعربية (كاميرا، صور، بصمة) | كانت موجودة ✅ |
| `scheme: commerco` للروابط العميقة | كان موجوداً ✅ |
| مُرسِل APNs على الخادم (JWT ES256 عبر HTTP/2) | كان موجوداً ✅ |
| رمز الجهاز الأصلي لا رمز Expo | كان موجوداً ✅ |
| النقر على الإشعار ← تفاصيل الطلب (خلفية + إقلاع بارد) | كان موجوداً ✅ |
| تسجيل الجهاز مربوطاً بالمتجر، بلا تكرار | كان موجوداً ✅ |
| **`aps-environment` مثبّت حسب ملف البناء** | **أُصلح** ⬅ |
| **`APNS_BUNDLE_ID` ضمن فحص الإعداد** | **أُصلح** ⬅ |
| **الصوت المخصص يظهر صحيحاً في تشخيص iOS** | **أُصلح** ⬅ |
| **سكربتات بناء iOS** | **أُضيفت** ⬅ |
| **`verify-ios-config.mjs`** | **أُضيف** ⬅ |

### الفخّ الذي أُصلح

ملحق `expo-notifications` يكتب `aps-environment` في الاستحقاقات **بلا شرط**،
وقيمته الافتراضية `development` — فيمحو قيمة `production` المكتوبة في
`app.json`.

لا يظهر أي خطأ. التطبيق يُوقَّع ويُثبَّت ويُسجَّل، لكنه يُصدر رموز **sandbox**
بينما الخادم يرسل إلى `api.push.apple.com`، فيعود كل إرسال بـ`BadDeviceToken`
ولا تسمع شيئاً أبداً.

الآن القيمة مثبّتة حسب ملف البناء، ومكتوبة في الاستحقاقات أيضاً حتى لا يختلفا:

| ملف البناء | التوقيع | `aps-environment` | `APNS_USE_SANDBOX` |
|---|---|---|---|
| `expo run:ios` محلياً | development | `development` | `true` |
| `preview` | ad-hoc | `production` | غير مضبوط |
| `production` | App Store | `production` | غير مضبوط |

## 2 · ما بقي — وكلّه بيدك أنت

**كل ما تبقّى يحتاج حساب Apple Developer المدفوع (99 دولاراً سنوياً).**

هذه حقيقة لا التفاف عليها، وقلتَ إنك لا تريد إخفاءها:

- **Push Notifications على iOS تتطلب مفتاح APNs**، ومفتاح APNs لا يُصدَر إلا
  من حساب Apple Developer مدفوع.
- الحساب المجاني يسمح بتشغيل التطبيق على جهازك سبعة أيام فقط، **وبلا
  إشعارات Push إطلاقاً**. وبما أن الإشعار هو هدفك الأساسي، الحساب المجاني
  لا يحقق ما تريد.

لم أستخدم أي شهادة غير رسمية ولن أفعل.

## 3 · الأوامر بالضبط

### أ — سجّل في Apple Developer

<https://developer.apple.com/programs/enroll/> · 99 دولاراً سنوياً.
التفعيل يستغرق من ساعات إلى يومين.

### ب — أنشئ مفتاح APNs

1. <https://developer.apple.com/account/resources/authkeys/list>
2. **+** ← الاسم `COMMERCO Push` ← فعّل **Apple Push Notifications service (APNs)**
3. **Continue** ← **Register** ← **Download**

ينزل ملف `AuthKey_XXXXXXXXXX.p8`.

> ⚠️ **يُنزَّل مرة واحدة فقط.** احفظه في مكان آمن. لا تضعه في المستودع أبداً.

من نفس الصفحة سجّل:
- **Key ID** — العشرة أحرف في اسم الملف
- **Team ID** — أعلى يمين الصفحة، أو في Membership

### ج — أضف الأسرار إلى Vercel

**من واجهة Vercel، لا من هنا** — أنا لا يجب أن ألمس مفاتيحك:

<https://vercel.com/> ← المشروع ← Settings ← Environment Variables

| المتغير | القيمة |
|---|---|
| `APNS_KEY_P8` | محتوى ملف `.p8` كاملاً مع سطري BEGIN/END |
| `APNS_KEY_ID` | الـKey ID (10 أحرف) |
| `APNS_TEAM_ID` | الـTeam ID (10 أحرف) |
| `APNS_BUNDLE_ID` | `store.commerco.merchant` |

ثم أعد النشر (Deployments ← آخر نشر ← Redeploy).

### د — ابنِ التطبيق

**لا تحتاج جهاز Mac.** EAS يبني على macOS في السحابة.

```bash
cd apps/mobile && npx eas-cli build --platform ios --profile preview
```

سيسألك EAS تسجيل الدخول بحساب Apple، ثم يتولّى بنفسه إنشاء شهادة التوزيع
وملف التزويد ورفع مفتاح APNs. أجب:

- `Do you want to log in to your Apple account?` → **Yes**
- `Generate a new Apple Distribution Certificate?` → **Yes**
- `Generate a new Apple Provisioning Profile?` → **Yes**

سيطلب تسجيل جهازك في ملف ad-hoc. عند السؤال اختر **Yes**، وسيعطيك رابطاً أو
QR — افتحه من iPhone وثبّت ملف التسجيل. أو سجّله مسبقاً:

```bash
cd apps/mobile && npx eas-cli device:create
```

### هـ — ثبّت على iPhone

بعد انتهاء البناء يعطيك EAS رابطاً. افتحه **من iPhone نفسه** وثبّت.

ثم: **الإعدادات ← عام ← VPN وإدارة الأجهزة ← ثِق بالمطوّر**.

### و — اختبر الإشعارات

1. افتح التطبيق وسجّل الدخول
2. اقبل إذن الإشعارات عند ظهوره
3. **الإعدادات ← الإشعارات ← «اختبار من الخادم»**
4. أغلق التطبيق تماماً ← يجب أن يصل الإشعار مع الصوت
5. اطلب طلباً حقيقياً من متجرك ← يجب أن يصل خلال ثوانٍ
6. اضغط الإشعار ← يجب أن يفتح **ذلك الطلب** لا الصفحة الرئيسية

قبل البناء، تحقّق أن الإعداد سليم:

```bash
cd apps/mobile && EAS_BUILD_PROFILE=preview npm run test:ios-config
```

## 4 · حدود iOS التي لا يتجاوزها أحد

هذه قيود نظام، لا عيوب في التطبيق، ولا أحد يتجاوزها — لا Shopify ولا غيره:

- **الوضع الصامت**: لا صوت. الإشعار يصل ويظهر، بلا صوت.
- **التركيز / عدم الإزعاج**: الإشعار مُعلَّم `time-sensitive`، وهذا يسمح له
  بالاختراق **إذا** سمح المستخدم بذلك في إعدادات التركيز. ليس مضموناً.
- **التطبيق مُنهى**: الإشعار يصل ويرنّ (يتولّاه النظام لا التطبيق). النقر
  يفتح التطبيق على الطلب — وهذا مُعالَج عبر `getLastNotificationResponseAsync`.
- **الشارة**: تُضبط من الخادم بعدد الطلبات الجديدة.

الصوت لا يُستخدم إلا لإشعار الطلب الجديد؛ تحديثات الطلب العادية لا تستدعيه.

## 5 · إن فشل شيء

| العرض | السبب الأرجح |
|---|---|
| `APNs not configured` | متغيّر من الأربعة ناقص في Vercel |
| `400 BadTopic` | `APNS_BUNDLE_ID` ≠ `store.commerco.merchant` |
| `400 BadDeviceToken` | تعارض بيئة: بناء development مع `APNS_USE_SANDBOX` غير مضبوط |
| `403 InvalidProviderToken` | خطأ في Key ID أو Team ID أو محتوى `.p8` |
| `410` | الجهاز ألغى التثبيت — الخادم يحذف الرمز تلقائياً |
| يصل بلا صوت | الوضع الصامت، أو `sound_enabled` مغلق لهذا الجهاز |

`npm run test:ios-config` يمسك أغلب هذه قبل البناء.
